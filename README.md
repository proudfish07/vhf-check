# VHF 活動訊號檢查（GitHub Pages 靜態網頁）

照養員上山用 TR8 錄的 10–15 分鐘錄音，丟進網頁就會自動找出發報器的「活動訊號」段落，
逐段播放確認後判定個體狀態。整個網頁只有 `index.html` 一個檔，音檔只在使用者的瀏覽器內分析，不會上傳。

## 判斷原理

發報器靜止時約 **1.52 秒**一聲（約 40 聲/分），一動就切換成約 **0.51 秒**一聲（約 118 聲/分）。
網頁抓出每一聲嗶聲後，找「間隔為 0.51 秒（或其 2 倍，容許漏 1 聲）、連續 ≥5 聲」的串列當作活動段落；
剩下的嗶聲再找「間隔為 1.52 秒整數倍」的串列當作休息訊號。訊號變弱時漏收的嗶聲，間隔仍是 1.52 秒的整數倍，
所以不會被誤判為活動。

判定：人工確認後的活動訊號 ≥ 10 秒 → 正常；不足 → 異常，應進入搜索。門檻、計算方式（累計或單段連續）、
兩種間隔都可在「進階設定」修改。

## 發布到 GitHub Pages

1. 在 GitHub 建一個新的 repository（例如 `vhf-check`）。
2. 把本資料夾的 `index.html` 上傳到 repository 根目錄。
3. Settings → Pages → Source 選 `Deploy from a branch`，Branch 選 `main`、資料夾 `/ (root)`，按 Save。
4. 約一分鐘後網址會出現在同一頁，例如 `https://<帳號>.github.io/vhf-check/`。

> 不要把錄音檔或 `_test_clips/` 推上去，公開的 repository 任何人都能下載。

## 本機測試

```
python -m http.server 8765
```

然後開 `http://localhost:8765/web/index.html?src=../_test_clips/260806_1913_active_12min.mp3`
（`?src=` 只接受同網站的相對路徑，方便測試，不影響正式使用）。

## 已驗證

| 測試檔 | 結果 |
|---|---|
| 小穿 260806 19:13 起 12 分鐘（真實活動） | 偵測活動 18 段，最長 64 秒；實測間隔 0.509 / 1.523 秒 |
| 小穿 260806 開頭 10 分鐘（休息、訊號斷續） | 全段休息，0 段活動（舊版 vhf_monitor 誤判為活動） |
| 小穿 260806 19:58 起 10 分鐘（收不到） | 0 聲嗶聲，無訊號 |
| 範例／休息訊號.mp3 | 休息，0 段活動 |
| 範例／活動訊號.mp3 | 2 段活動（8 秒、3.6 秒），同時有 1.52 秒的休息節奏 |

一般電腦分析 12 分鐘音檔約 3–6 秒。WMA / AMR 格式瀏覽器無法解碼。
